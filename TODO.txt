PAC-MAN - ETAT D'AVANCEMENT ET RESTE A FAIRE
=============================================

Fichier principal actuel : renderer.py (classes render, Player, Phantom,
fonction reset_pos, et la boucle principale sous "if __name__ == '__main__'").
A lancer depuis le dossier pacman/ (les images et config.txt sont lus en
chemin relatif).


DEJA FAIT
---------
- Labyrinthe affiche (fond noir, murs bleus, cases "42" pleines), generation
  via mazegenerator (niveau 1 = graine 42, ensuite aleatoire).
- Pac-Man deplace aux fleches, pacgums et super pacgums (aux 4 coins).
- 4 fantomes (BFS vers le joueur), vulnerables apres une super pacgum
  (fuite), mangeables (+200), retour a leur coin.
- Vies (3), score (10 / 50 / 200), chrono par niveau (90 s), HUD.
- Changement de niveau, fin au niveau 10 (niveau_max).
- Machine a etats (variable "state") : menu, jeu, pause, game_over, victoire.
- Menu principal : Start / Highscores / Instructions / Exit (navigation aux
  fleches + Entree), titre "Pac-Man". Start et Exit fonctionnent.
- Pause avec Echap (le chrono est fige correctement).
  Connu et accepte : les timers de vulnerabilite des fantomes ne sont pas
  figes pendant la pause.
- Ecrans Game Over et Victoire (affichent le score).


A FAIRE (par ordre conseille)
-----------------------------

1) Ecrans / etats
   - Ecran Instructions : etat "instructions" (texte + Echap pour revenir au
     menu). Brancher l'entree "Instructions" du menu (choix == 2).
   - Retour au menu apres game_over / victoire (touche Entree) avec
     REINITIALISATION COMPLETE de la partie :
       vies = 3, score = 0, level = 1, new_maze(1), vider puis replacer les
       pacgums et super pacgums, reset_pos, fantomes eat = False, chrono
       (start) remis a zero.
     Idee : une fonction nouvelle_partie(...) appelee a chaque "Start".
   - Menu de pause : Resume / Return to main menu.

2) Highscores
   - Fichier JSON, top 10. Nom : 10 caracteres max, lettres/chiffres/espaces.
     Score : entier positif.
   - Fichier absent ou corrompu : ne jamais planter (liste vide).
   - Saisie du nom a la fin d'une partie (game_over et victoire).
   - Ecran Highscores depuis le menu (le sujet en montre un exemple avec le
     top affiche sur l'ecran d'accueil).

3) Configuration (exigence du sujet)
   - Fichier JSON avec commentaires "#", lance par :
       python3 pac-man.py config.json
   - Fichier invalide / valeurs hors limites : valeurs par defaut, aucun
     traceback.
   - Sortir du code les valeurs en dur : vies, points (10/50/200),
     nb_pacgums, temps max par niveau, nombre de niveaux, vitesses (joueur
     0.05, fantomes 0.04 : doivent diviser 1 exactement), durees (6000 ms
     vulnerabilite, 5000 ms fantome mange), taille du labyrinthe par
     niveau, graine.
   - Actuellement config.txt est au format cle=valeur : il faut passer au
     JSON. Lire les chemins relativement a __file__.
   - Les textes de l'ecran Instructions contiennent des nombres en dur : les
     construire avec les variables de config.

4) Mode triche
   - Invincibilite, passer un niveau, geler les fantomes, vies en plus,
     vitesse, etc. (activation au choix, par exemple une touche).

5) Labyrinthe
   - Verifier que mazegenerator/ est bien le package A-Maze-ing fourni, a
     utiliser TEL QUEL (PERFECT=False). Gerer proprement un echec de
     generation.
   - Taille du labyrinthe lisible depuis la config, par niveau.

6) Nettoyage du code
   - Code mort : Player.check_wall (utilise le global "re"), dedede.py,
     Ubuntu.png non utilise, main.py quasi vide.
   - reset_pos utilise "play" en global : le passer en parametre, et remettre
     eat / direction a zero.
   - Variables magiques a nommer, doublons a factoriser (les deux ecrans de
     fin sont presque identiques).

7) Qualite (exigee par le sujet)
   - flake8 et mypy sans erreur, type hints partout, docstrings.
   - Decouper en modules ; le point d'entree doit s'appeler pac-man.py.
   - Makefile : install, run, debug, clean, lint (et lint-strict).
   - .gitignore.
   - README en anglais, premiere ligne en italique :
       *This activity has been created as part of the 42 curriculum by <login>.*
   - Dossier de gestion de projet.
   - Packaging itch.io / Steam.

8) Bonus (plus tard)
   - Comportements differents des fantomes : un qui chasse, un qui suit la
     trace du joueur, un "debile" aleatoire, un qui fuit. Eviter les demi-tours
     pour la fuite.


NOTES
-----
- La variable "state" gouverne tout : "state = ..." CHANGE l'etat,
  "if state == ...:" le TESTE.
- Tout ce qui doit se souvenir d'une image a l'autre (choix du menu, options,
  start...) doit etre defini AVANT le "while continuer:".
- Les coordonnees du joueur et des fantomes sont des flottants (cases) :
  at_center() utilise une tolerance de 0.001.
