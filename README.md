# Pac-Man

## Description

A complete, playable Pac-Man written in Python 3.10+ with
[pygame](https://www.pygame.org/). The goal of the activity is to build a
game with a modular object-oriented architecture, a configurable ruleset, a
persistent highscore table and mazes produced by an external package
(*A-Maze-ing*), and to package it for a public gaming platform.

Features:

- 10+ levels, each one a maze generated by the assigned `A-Maze-ing`
  package (fixed seed for level 1, random afterwards), with a time limit.
- Player starts in the middle with 3 lives; 4 ghosts start in the corners;
  super-pacgums in the 4 corners make the ghosts edible for a while.
- Main menu, instructions, highscores, in-game HUD, pause menu, game over
  and victory screens, name entry for the highscores.
- JSON configuration file with comments, robust defaults, no traceback.
- Persistent top 10 highscores stored in a JSON file.
- Cheat mode for peer review.

## Instructions

### Installation

```console
$ make install        # pip install -r requirements-dev.txt
```

Only `pygame` is needed to play (`pip install -r requirements.txt`).

### Run

```console
$ python3 pac-man.py config.json      # or: make run
```

The program takes exactly one argument: the configuration file. Any problem
with that file (missing, invalid JSON, wrong values) is reported on stderr
and replaced by safe defaults; the game never exits with a traceback.

### Controls

| Key | Action |
|---|---|
| Arrows, `W A S D` or `Z Q S D` | Move Pac-Man |
| `Esc` | Pause / resume (in game), back (in sub-screens) |
| `Up` / `Down` + `Enter` | Navigate menus |
| `C` | Toggle the cheat mode |

### Cheat mode

Press `C` during a game: a red `CHEAT` label appears in the HUD, followed
by the letters of the active effects. While it is on:

| Key | Effect |
|---|---|
| `I` | Invincibility: ghosts and the level clock cost no life |
| `F` | Freeze the ghosts |
| `V` | Faster player (`player_cheat_speed`) |
| `L` | One extra life |
| `N` | Skip (win) the current level |

Pressing `C` again turns the mode and all its effects off.

### Make targets

| Target | Description |
|---|---|
| `make install` | Install the dependencies (game + dev tools) |
| `make run` | Run the game with `config.json` (`make run CONFIG=other.json`) |
| `make debug` | Run the game under `pdb` |
| `make clean` | Remove `__pycache__`, `.mypy_cache`, `.pytest_cache`, build output |
| `make lint` | `flake8 .` and `mypy .` with the mandatory flags |
| `make lint-strict` | `flake8 .` and `mypy . --strict` |
| `make test` | Run the unit tests (`pytest`) |
| `make package` | Build the distributable with PyInstaller (`pac-man.spec`) |

### Packaging

`make package` builds `dist/pac-man/` (executable, assets and a default
`config.json`) from `pac-man.spec` and `packaging_launcher.py`. The folder
is zipped and uploaded to itch.io as a private/unlisted build, for example
with [butler](https://itch.io/docs/butler/):

```console
$ butler push dist/pac-man <user>/<game>:windows
```

The packaged game needs no argument: it uses the `config.json` next to the
executable (or the bundled one). Highscores are written next to the
configuration file.

## Configuration

The file is JSON in which every line starting with `#` (or `//`) is a
comment. **Every key is optional.** A missing key gets its default; a value
of the wrong type gets its default; an out-of-range number is clamped. In
each case a clear `[config]` message is printed and the game continues.
Unknown keys are ignored.

| Key | Default | Allowed | Meaning |
|---|---|---|---|
| `highscore_filename` | `highscores.json` | non-empty string | Highscore file, relative to the config file |
| `lives` | 3 | 1-99 | Lives at the start |
| `pacgum` | 200 | 1-2000 | Pacgums per level (limited by free cells) |
| `points_per_pacgum` | 10 | 0-10000 | Score of a pacgum |
| `points_per_super_pacgum` | 50 | 0-10000 | Score of a super-pacgum |
| `points_per_ghost` | 200 | 0-10000 | Score of an edible ghost |
| `seed` | 42 | 0-2^31-1 | Seed of level 1 (0 = random) |
| `level_max_time` | 90 | 5-3600 | Seconds per level |
| `levels` | 10 levels of 15x15 | list, 10 to 50 entries | `{"width", "height"}` of each maze (10-60 cells); shorter lists are padded to 10 levels |
| `window_width` / `window_height` | 1500 / 600 | 400-3000 / 400-2000 | Largest window; the cell size adapts |
| `player_speed` | 0.05 | 0.005-0.5 | Cells per frame |
| `player_cheat_speed` | 0.1 | 0.005-0.5 | Cells per frame with `V` |
| `ghost_speed` | 0.04 | 0.005-0.5 | Cells per frame (halved when edible) |
| `vulnerable_duration_ms` | 6000 | 500-60000 | Edible time after a super-pacgum |
| `ghost_respawn_ms` | 5000 | 500-60000 | Time before an eaten ghost comes back |
| `wall_color` / `background_color` | `[33,33,222]` / `[0,0,0]` | `[r, g, b]` | Colors |

The provided `config.json` documents each key with comments.

## Highscore

The top 10 scores are stored in a JSON file
(`[{"name": "Alice", "score": 1200}, ...]`), next to the configuration
file. We chose JSON because it is human readable, easy to validate and
needs no dependency, and a single small file is enough for 10 entries.

- Loaded at game start and when the highscore screen is opened; shown in
  the main menu (top 3) and on the *View Highscores* screen (top 10).
- Saved at the end of a game (game over **or** victory), after the player
  types a name (`Esc` skips saving).
- Names: 1 to 10 characters, ASCII letters, digits and spaces (an empty
  name becomes `Anonymous`). Scores: non-negative integers.
- Robustness: a missing, unreadable or corrupted file gives an empty
  table; invalid entries are skipped; a write error is reported but never
  crashes the game. The file is written to a temporary file and then
  atomically renamed, so a crash cannot truncate it.

## Maze Generation

Mazes come from the assigned **A-Maze-ing** package (`mazegenerator/`).
`pacgame/maze.py` adapts to its interface (it is the only module importing
it): `MazeGenerator(size=(width, height), perfect=False, seed=seed)` and the
`maze` attribute, a grid of wall bit masks (north=1, east=2, south=4,
west=8; 15 = closed cell of the "42" pattern). `PERFECT` is always `False`
so that corridors loop, as Pac-Man needs.

- Level 1 uses the configured `seed` (reproducible); later levels use seed
  `0` (random). The size of each level comes from `levels` in the config.
- If the generator fails, the error is reported cleanly: at game start a
  message is shown in the menu, between levels the previous maze is kept.
- The player starts on the free cell nearest to the center (the "42"
  pattern can cover the exact center); ghosts and super-pacgums use the
  four corners.

## Implementation

- **State machine** (`pacgame/game.py`): `menu`, `instructions`,
  `highscores`, `playing`, `paused`, `game_over`, `victory`, `name_entry`.
  One handler per state; the main loop runs at 30 FPS.
- **Movement**: entities live on float cell coordinates (integers are cell
  centers). `entities.step()` never lets a move cross a center without
  landing exactly on it, so entities cannot drift off the grid at any
  speed. Turns are taken at centers; the player may U-turn at any time.
- **Ghosts**: when not edible they follow the shortest path (breadth-first
  search) to the player's cell; when edible they walk away from the player
  at half speed. Eaten ghosts return to their corner after
  `ghost_respawn_ms`.
- **Time**: the game keeps a counter of *played* milliseconds that does not
  advance during the pause, so the level clock, edible and respawn timers
  all freeze naturally while paused.
- **Rendering**: the walls of a maze are drawn once on a surface per level
  and blitted every frame. The window is resized for each maze.

## General Software Architecture

```
pac-man.py            entry point (argument parsing)
packaging_launcher.py entry point of the packaged build
pacgame/
  config.py           JSON-with-comments loader, validation, GameConfig
  highscores.py       top 10 storage (JSON)
  maze.py             A-Maze-ing wrapper, wall decoding, BFS
  level.py            Level: maze, start cells, pacgums
  entities.py         Player, Ghost, movement helpers
  renderer.py         window, maze/HUD/menu drawing
  game.py             Session (rules, cheats) and Game (state machine)
  assets.py           image loading
assets/               sprites
mazegenerator/        assigned A-Maze-ing package
tests/                pytest unit tests
project-management/   planning, risks, tests, decisions
```

`Game` owns a `Renderer` and, while a game is running, a `Session`. The
`Session` owns the `Player`, the `Ghost`s and the `Level`, applies the rules
(scoring, lives, levels, cheats) and never draws by itself except through
the renderer. `config.py`, `highscores.py` and `maze.py` do not depend on
pygame.
